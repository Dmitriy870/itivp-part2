# API платформы профессиональной переподготовки

Локальный базовый URL: `http://localhost:3000`. Production через frontend-proxy: `http://207.180.199.246:8080/api`.

Все тела запросов передаются как JSON с заголовком `Content-Type: application/json`. Access-токен передаётся так:

```http
Authorization: Bearer <accessToken>
```

Refresh-токен сервер устанавливает в cookie `refreshToken` с флагами `HttpOnly` и `SameSite=Strict`. Формат успешного ответа: `{ "data": ... }`. Формат ошибки:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Ошибка валидации данных",
    "details": [{ "field": "email", "message": "..." }]
  }
}
```

В production безопасные подробности ошибок входной валидации возвращаются в `details`.
Внутренние причины серверных ошибок не раскрываются.

## Матрица ролей

| Операция | user | moderator | admin |
| --- | :---: | :---: | :---: |
| Просмотр курсов | + | + | + |
| Создание курса | + | + | + |
| Изменение собственного курса | + | + | + |
| Изменение чужого курса | - | - | + |
| Удаление курса | - | - | + |
| Просмотр/изменение пользователей | - | - | + |
| Запись на курс и личный кабинет | + | + | + |

`roleGuard(requiredRole)` использует иерархию `user < moderator < admin`.

## Аутентификация

### POST `/auth/register`

Публичная регистрация. Роль всегда назначается сервером как `user`; передача `role`, `id`, `passwordHash` и других неизвестных полей отклоняется.

```json
{
  "email": "student@example.com",
  "password": "Strong123!"
}
```

Пароль: 8-72 символа, минимум одна заглавная и одна строчная буква, цифра и специальный символ. Ответ: `201 Created`. Возможные ошибки: `400`, `409`, `415`, `429`.

### POST `/auth/login`

```json
{
  "email": "student@example.com",
  "password": "Strong123!"
}
```

Ответ `200` содержит `accessToken`, а refresh JWT устанавливается cookie. После пяти ошибок аккаунт блокируется на 15 минут. Неверные данные возвращают одинаковую ошибку `INVALID_CREDENTIALS`.

### POST `/auth/refresh`

Не требует тела; использует cookie. Старый refresh-токен отзывается, создаётся новый. Повторное использование старого токена отзывает активные сессии пользователя.

### POST `/auth/logout`

Отзывает текущий refresh-токен и очищает cookie. Ответ: `204 No Content`.

### GET `/auth/me`

Требует access JWT. Возвращает безопасный DTO пользователя без `passwordHash`, счётчика ошибок и refresh-токенов.

## Курсы

### GET `/courses`

Публичный маршрут. Query-параметры:

- `page` — страница, от 1;
- `limit` — количество, 1-100;
- `search` — регистронезависимый поиск по части названия;
- `category` — поиск категории;
- `format` — `online`, `webinar` или `mixed`;
- `published` — `true` или `false`.

Ответ содержит `data` и объект `pagination`.

### GET `/courses/:id`

Публичный маршрут. `id` — UUID v4. Ответы: `200`, `400` при неверном UUID, `404` при отсутствии курса.

### POST `/courses`

Доступ: любой аутентифицированный пользователь. Автор курса определяется сервером по JWT и сохраняется в поле `createdBy`.

```json
{
  "title": "Безопасная разработка REST API",
  "description": "Программа переподготовки по безопасности серверных приложений.",
  "category": "Информационные технологии",
  "format": "online",
  "durationHours": 420,
  "price": 1750,
  "certificateIssued": true,
  "webinarUrl": "https://webinars.example.com/secure-api",
  "published": true
}
```

`createdBy`, `id`, `createdAt` и `updatedAt` назначаются сервером. HTML-символы `<` и `>` в текстовых полях отклоняются. Ответ: `201 Created` и заголовок `Location`.

### PUT `/courses/:id`

Доступ: автор курса или `admin`. Полностью заменяет редактируемые поля курса. Тело совпадает с POST. Попытка изменить чужой курс возвращает `403 COURSE_UPDATE_FORBIDDEN`.

### DELETE `/courses/:id`

Только `admin`. Ответ: `204 No Content`.

## Записи на обучение

Все маршруты требуют access JWT. Пользователь работает только со своими записями.

### GET `/enrollments/me`

Возвращает программы текущего пользователя вместе с данными каждого курса и датой записи.

### POST `/enrollments/:courseId`

Записывает текущего пользователя на опубликованный курс. Повторная запись возвращает
`409 ALREADY_ENROLLED`. Ответ при создании: `201 Created`.

### DELETE `/enrollments/:courseId`

Отменяет запись текущего пользователя. Ответ: `204 No Content`.

## Пользователи

Все маршруты раздела доступны только `admin` и записываются в security audit log.

### GET `/users`

Возвращает безопасные DTO пользователей.

### PUT `/users/:id/role`

```json
{ "role": "moderator" }
```

Администратор не может изменить собственную роль.

### DELETE `/users/:id`

Удаляет пользователя. Администратор не может удалить собственную учётную запись.

## Служебные маршруты

### GET `/health`

Возвращает состояние приложения и базы данных, текущую дату, uptime, память и идентификатор release. При недоступной БД отвечает `503` без раскрытия внутренней ошибки.

### GET `/metrics`

Возвращает метрики в формате Prometheus: uptime и память Node.js, число активных запросов, суммарный счётчик запросов и histogram задержки. В production через frontend доступен как `/api/metrics`; Prometheus обращается к нему только по внутренней Docker-сети.

### POST `/debug/error`

Production-маршрут для однократной проверки Sentry. Требует секретный заголовок `X-Debug-Token`; при неверном или отсутствующем токене маскируется под `404`. Маршрут существует только при `ENABLE_TEST_ENDPOINTS=true`.

## Основные HTTP-статусы

| Статус | Значение |
| --- | --- |
| 200 | Запрос выполнен |
| 201 | Ресурс создан |
| 204 | Успешно, тело отсутствует |
| 400 | Ошибка валидации или JSON |
| 401 | Нет или недействительна аутентификация |
| 403 | Недостаточно прав / CORS forbidden |
| 404 | Ресурс или маршрут не найден |
| 409 | Конфликт уникальных данных |
| 415 | Требуется `application/json` |
| 423 | Учётная запись временно заблокирована |
| 429 | Превышен rate limit |
| 500 | Внутренняя ошибка без утечки деталей |
